# دليل مشروع عمارتي (Amarati) — شرح شامل بالعربية

هذا الملف يشرح **فكرة التطبيق**، **التقنيات**، **ربط قاعدة البيانات**، **طريقة العمل داخل الكود**، و**دور الملفات والمجلدات الرئيسية**.  
اسم الحزمة في `package.json`: `amarati1` — واجهة ويب لتسجيل السكن وإدارة المبنى (لوحة، صيانة، تصويتات، إعلانات، شات مجموعة، جواز وحدة، مشرف، مساعد ذكي تجريبي).

---

## 1. ماذا يفعل التطبيق للمستخدم النهائي؟

**سياسات الحساب (حسب المتطلبات الحالية للمنتج):**

- **رقم الجوال إلزامي** وفريد في النظام؛ **البريد الإلكتروني اختياري**؛ **لا توجد صورة شخصية**. تسجيل الدخول بـ المعرف (`identifier`) يمكن أن يكون رقم جوال أو بريداً إن وُجد في الحساب.
- بعد **إنشاء حساب جديد** أو عند وجود حساب بدون تأكيد الجوال بعد تغييره، يظهر مسار **التحقق برمز OTP (SMS)** عبر صفحة مخصّصة قبل الوصول الطبيعي للوجهة (مثل لوحة المبنى).

**التجربة الأساسية:**

- **تسجيل وتسجيل دخول**: كلمة مرور؛ إنشاء حساب عبر **إنشاء مبنى جديد** أو **الانضمام برمز المبنى ورقم الوحدة**، ثم **تأكيد الجوال**.
- **لوحة التحكم والمباني**: اختيار مبنى مرتبط بالعضوية وفتح صفحات تابعة له.
- **داخل المبنى**: نظرة عامة، **الصيانة** (طلبات شخصية/جماعية مع تحليل نصي وتكامل اختياري لنموذج ML) — دون قائمة أو تعاقد مع **شركات صيانة داخل التطبيق**؛ **التصويتات** تشمل أساساً **التصويت على المشرف** وأنواع أخرى تظهر وفق المنطق الحالي؛ **الإعلانات**؛ **شات الجماعة**؛ **جواز الشقة**؛ **دعوات/رمز المبنى**؛ **لوحة المشرف**؛ **مساعد ذكي**؛ **شات بوت الاستخدام**.
- **الدفع (Payment)** وواجهات معالجة مدفوعات **غير مدمجة في واجهة المنتج** الحالية (قد تبقى أسماء النماذج في مخطط Prisma لتوريث قواعد أو هجرات؛ لا تعتمد عليها في التصميم الوظيفي).
- **تحليل أو اقتراح صيانة بتوجُّه تنبؤي**: يدمج ضمن النص أو السياق التحليلي للصيانة دون تجربة واجهة منفصلة ك«تنبيهات صيانة تنبؤية» في الشكل المعتمد حالياً.
- **حساب ومظهر**: ملف شخصي، لغة عربي/إنجليزي، إعدادات محلية (مظهر/إشعارات) في المتصفح.

الشات الجماعي **ليس** «real-time» بالمعنى الشائع (لا WebSocket)، و**لا** يستخدم **HTMX**؛ يعتمد على إرسال النموذج وServer Action ثم تحديث الصفحة (راجع القسم 13).

## 3. الربط مع قاعدة البيانات

- **الملف المرجعي**: `prisma/schema.prisma`
- **الاتصال السريع للتطبيق**: `DATABASE_URL` (غالباً مع **connection pooler** مثل Supabase PgBouncer).
- **الاتصال المباشر للهجرات**: `DIRECT_URL` (مضيف قاعدة الفعلي؛ **لا** يُستعمل pooler الذي يمنع قفل الهجرة).
- **في الكود**: ملف `src/lib/prisma.ts` يصدّر عميل Prisma مفرد (يُفضّل لتفادي اتصالات زائدة على serverless).

تهيئة أولية محلية شائعة:

```bash
npm install
npx prisma migrate deploy   # أو prisma migrate dev للتطوير
npm run dev
```

مجلد **`prisma/migrations/`** يحتوي ملفات SQL تاريخية لكل تغيير في المخطط — لا تُحرّر يدوياً إلا بحذر؛ التعديل المعتاد عبر `schema.prisma` ثم أمر هجرة.

## 5. المصادقة والجلسة

- **`src/lib/session.ts`**: قراءة/كتابة تعريف مستخدم الجلسة في **Cookie** مشفّرة/موقّعة باستخدام `AUTH_SECRET`.
- **`src/lib/current-user.ts`**: `getCurrentUser()` يجلب المستخدم من الجلسة والقاعدة (مع `cache` لطلب واحد).
- **`src/actions/auth.ts`**: تسجيل دخول (مع إجبار تأكيد الجوال عبر OTP إن لم يُثبَّت `phoneVerifiedAt`)، خروج، تحديث ملف شخصي، إصدار OTP، التحقق من الرمز، إعادة الإرسال — يستفيد من **Twilio Verify** أو **رمز مخزَّن محلياً** حسب المتغيرات (راجع `src/lib/twilio-verify.ts` و `sms-otp.ts`).
- **`src/actions/signup.ts`**: إنشاء المستخدم بحقل **`phoneVerifiedAt` فارغ** حتى تأكيد الرمز؛ تهيئة **`emailVerifiedAt`** وفق المنطق الموجود في الكود (`signup.ts`) عندما يكون البريد فارغاً أو مملوءاً؛ إنشاء البنية (مبنى/عضوية أو انضمام)؛ استدعاء **`issuePhoneOtpForUser`**؛ ثم **`createSession`**؛ ثم **`redirect`** إلى **`/register/verify-phone`** مع وسائط **`phone`** و **`next`** (عادة مسار **`/building/{id}`**) حتى يدخل الرمز ويُثبَّت الجوال.

صفحة **`/register/verify-phone`**: نموذج تأكيد الرمز وزر إعادة الإرسال، مع حقل مخفي **`next`** للعودة بعد النجاح.

لا يوجد `middleware.ts` في الجذر؛ الحماية عبر فحص `getCurrentUser()` داخل الصفحات والإجراءات و`redirect` إلى `/login`.

## 13. ملاحظات سلوكية مهمة للعميل أو الفريق

1. **الشات الجماعي**: ليس تحديثاً فورياً دفعياً؛ الإرسال عبر **Server Action** ثم `revalidatePath` و`redirect` — المستخدم الآخر لا يرى الرسائل الجديدة حتى يُحدِّث الصفحة أو يُرسل هو رسالة أو يُعيد التحميل.
2. **HTMX**: غير مستخدم في المستودع.
3. **الجوال وبريد وOTP**: الجوال حقول أساسية في التسجيل؛ تأكيده عبر OTP بعد إنشاء الحساب؛ تغيير رقم الجوال من الملف الشخصي يعيد طلب OTP. البريد اختياري؛ حقول **`emailVerifiedAt`** قد تُحدَّث وفق المنطق الحالي بدون تجربة «تحقق بريدي» مطوّلة في كل الحالات (راجع **`auth`** ونماذج التسجيل).
4. **مخطط Prisma ومزود Supabase**: قد لا تكون كل الكيانات الظاهرة في **`schema.prisma`** (مثل **`Payment`** أو أنواع تصويت قديمة) موافقة لمخزَّن أو خدمات Supabase فعلاً؛ المصدر المعتمد للمنتج المنشور هو **الكود** ومسارات الواجهة، لا مجرد قائمة النماذج.
5. **شركات الصيانة والدفع**: لا تفرض هذه الميزات في توثيق المنتج أمام النهاية؛ إن وُجدت في قاعدة أو مخطّط تعامل معها على أنها وراثة وليست ميزات مفعّلة.
6. **الأمان**: لا ترفع ملف `.env` الحقيقي إلى Git؛ استخدم `.env.example` كمرجع فقط.
